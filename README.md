## Purpose and Functionality

A collection of tools to analyze model runs.

## Python package

The Python port of **modelstats** (same version, `pyproject.toml`) ships the `rs` command, the public `Run`
object and the `modeltests` command. It was developed phase by phase with the R package as the oracle: every
table `rs` prints is compared byte for byte with goldens generated by the R code in a sandbox. The plan, the
decision table, the bug register, the goldens and the sandbox harness form the migration record, which is
kept outside the repository (see "The migration record" below). The R package described further below stays
in the repository for the transition.

### Installation with uv

Python 3.14 or newer and [uv](https://docs.astral.sh/uv/); uv installs the interpreter itself when none is
present:

```sh
uv build                                                    # in the checkout: dist/modelstats-0.31.0-py3-none-any.whl and the sdist
uv tool install ./dist/modelstats-0.31.0-py3-none-any.whl   # the commands rs and modeltests, on a uv-managed CPython 3.14
uv tool install .                                           # the same, built straight from the checkout (a git URL works the same way)
uv tool upgrade modelstats
```

For development `uv sync --locked` creates `.venv` with the locked dependency set, `uv run rs` and
`uv run modeltests` run the commands from it and `uv run pytest -q` runs the unit tier (the golden and
sandbox tiers need the migration record, below). `uv run pytest -m golden tests/packaging` builds the
wheel, installs it into a fresh 3.14 environment and with `uv tool install`, and checks the installed
commands. On the cluster a shared environment is planned so that nobody installs anything (the transition,
below; a manual step).

The runtime dependencies: `gamsapi[transfer]` and `gamspy_base`
read GDX files without a GAMS installation, `rdata` reads `config.Rdata`, `runstatistics.rda` and the `.rds`
files, `pyyaml` reads MAgPIE's `config.yml`, `natsort` sorts run names, `typer` parses the command lines.
`rs` and `Run` need no R. The AMT host still needs `Rscript` (REMIND's `start.R` and its `selectScenarios()`,
which are REMIND code and are called, not ported).

### The `rs` command is a drop-in

`rs` is the command line of `R/commandLineInterface.R` with the same options, bundled short flags
(`rs -mltpbf PkBudg`), the same path argument (a comma-separated list of run folders, main folders or output
folders, `.` by default) and the same output: the tables on stdout, the messages on stderr, the same exit
status, byte for byte. Parity is verified against 101 `rs` goldens generated by the R package in a sandbox,
in process and end to end (the `rs` family of the migration record), on top of the goldens of the
functions below it (`getRunStatus`, `colRunType`, `foundInSlurm`, `printOutput`, `loopRuns`,
`getSanityChecks`). Suspected bugs of the R code are reproduced on purpose and recorded in the bug
register of the migration record (parity first; fixes are separate decisions).

| Option | Meaning (`rs --help`) |
|---|---|
| `-A`, `--amt` | the most recent REMIND automated model test runs; with `-f REGEX` only the AMT runs (archive included) matching `REGEX` |
| `-b`, `--nocolor` | black and white: the table without colours |
| `-C`, `--current` | the currently running runs wherever they are; `-u USER` for another user, `-d N` to include the runs of the last N days |
| `-d N`, `--daysback N` | only with `-C`: recent runs of the last N days (default 0) |
| `-f REGEX`, `--filter REGEX` | the runs matching the regular expression(s), several separated by comma (default `.*`) |
| `-l`, `--last` | only with `-m`: the last coupling iteration only |
| `-m`, `--magpie` | all coupling iterations (`C_*`, `*-rem-N`, `*-mag-N`) |
| `-p`, `--prompt` | choose the runs from a list before the table is printed |
| `-s`, `--sanity` | the sanity-check overview instead of the status table |
| `-t`, `--time` | sort the runs chronologically |
| `-u USER`, `--user USER` | only with `-C`: the runs of `USER` (default: you) |
| `--found-in-slurm DIR` | Python only: print `foundInSlurm(DIR)` and nothing else (for scripts, below) |
| `-h`, `--help` | the help page |

```sh
rs                        # the run in the working directory, or every run below it
rs -A -f SSP2-NPi         # the recent automated model tests matching a pattern
rs -C -u alf -d 5         # the current runs of user alf, the last 5 days included
rs -s path/to/output      # the sanity-check overview of the runs below output/
```

The differences from the R command are listed in the decision table of the migration record and nowhere
else. Approved: the layout of `rs --help` (D-11, typer's page with R's options), the
natural sort of the run names without the ICU collation (D-14), the random `Did you know?` hint (D-08) and
`rs -A` reading the AMT state file `amt-state.json` before `runcode.rds` (D-26). Unavoidable and pending: a
damaged GDX file aborts the R process with exit status 134 where `rs` prints `skipped because of error` for
that run (D-20), and `rs -p` with a piped stdin reads one line per prompt where R loses every line after the
first (D-21). Everything else, including a usage error (exit status 1 with optparse's message, D-12), is
parity.

### The `Run` object

```python
from modelstats import Run, RunState

run = Run("/p/projects/remind/modeltests/remind/output/SSP2-NPi-AMT_2026-09-28_10.30.27")
print(run.status, run.convergence, run.iterations.current, run.warnings, run.runtime)
if run.status is RunState.COMPLETED and run.convergence.is_converged:
    print(run.summation_errors, run.mif, run.to_status_record())
```

prints, for that run of the fixture snapshot, `RunState.COMPLETED Convergence.CONVERGED 26 27 2:18:23.765632`
and then `0 MifState.PRESENT RunStatus(run='SSP2-NPi-AMT_2026-09-28_10.30.27', ..., RunStatus='Normal completion',
..., Conv='converged', Runtime=8304, ...)`. `Run` reads a run folder the way `rs` does, lazily and at most once
per file, and presents the result with Python types (enums for the status, the convergence and the mif state,
numbers and `timedelta`, `None` for a missing value); `run.to_status_record()` is the R-compatible record `rs`
prints and `run.to_dict()` a JSON-able snapshot. Other repositories import it instead of re-implementing
`getRunStatus.R`. The full API, the `RunState` table and the deliberate differences from the R view are in
[docs/run-object.md](docs/run-object.md).

### The `modeltests` command

`modeltests` replaces the `Rscript -e 'modelstats::modeltests(...)'` line of the REMIND automated model tests
(AMT) cron job. It is a rewrite, REMIND only (the MAgPIE
weekly tests stay with the R package, D-27): `modeltests run` starts a cycle when none is running and
evaluates it otherwise (the drop-in for the old `.testsstatus` toggle); `start`, `evaluate`, `status` and
`reset` are the single steps. The global options go in front of the command: `--dir` (the REMIND checkout),
`--report-repo` (the clone that receives `README.md`), `--user`, `--mattermost-url-env` (default
`AMT_MATTERMOST_URL`; unset means no notification), `--publish/--no-publish`,
`--compare-scenarios/--no-compare-scenarios`, `--log-dir`, `--dry-run`, `--force` and `--no-wait`. One JSON
state file (`<dir>/amt-state.json`), one lock (`<dir>/amt-state.lock`) and one log per cycle
(`<log-dir>/amt-<cycle id>.log`) replace the `.testsstatus` toggle and the `.rds` state files; only
`runcode.rds` keeps being written, for `rs-r -A`. Exit statuses: 0 the command did what it says, 1 the cycle
crashed and the state is `failed` (a Mattermost message is sent when a URL is configured), 2 refused before
any effect. The cron lines, the state machine, the log, the recovery steps, `--dry-run` and what changed
against the R version are in [docs/amt.md](docs/amt.md), the operator's guide.

### `rs --found-in-slurm DIR` for scripts

REMIND's `readcoupled.R` asks whether a coupled run is still in SLURM. The Python command answers without
loading an R package: `rs --found-in-slurm DIR` prints exactly the string `foundInSlurm(DIR)` returns
(`no`, the QOS of the run's own job with ` startup` or ` pending` appended where R appends it, another
user's name, or `<n> users`) plus one newline on stdout and nothing else: no announcements, no hint, no
table; exit status 0. On an error it prints nothing on stdout, one message on stderr and exits 1. The
contract is pinned by `tests/golden/test_rs.py::test_found_in_slurm_contract` and checked on the installed
command by `tests/packaging/test_wheel.py`.

### The transition from the R package (`rs-r`)

The R package stays in this repository with the version the Python package mirrors
(`tests/unit/test_version.py`). The cut-over is the last phase of the migration plan and is manual (it
needs the cluster and the owners of the wrappers and the cron job):

- A shared environment on the cluster holds the Python package; the `rs` wrapper
  (`/p/projects/rd3mod/tools/rs`) switches to its `rs`, the R command line stays available as `rs-r`, and
  `RS_IMPL=r` is the escape hatch for one release. A parallel-run period compares `rs-r` and `rs` on the same
  captured inputs; every difference goes to the bug register.
- `rs -A`, `rs-r -A` and `remindstatus` agree while both packages exist: the Python AMT keeps writing
  `runcode.rds` next to its JSON state, and the Python `rs -A` reads the JSON first and falls back to
  `runcode.rds` (D-26).
- The first `modeltests` command on the cluster checkout derives its state once from `../.testsstatus`,
  `runcode.rds`, `runsToStart.rds` and `lastcommit.rds`, logs what it derived and leaves those files as they
  are. They are not updated afterwards (except `runcode.rds`), so a rollback to the R cron job means setting
  `.testsstatus` by hand to `next:start` or `next:evaluate` first.
- `remindstatus` keeps its `modelSummary` and summation-check parts and only swaps its modelstats call for
  `rs`; REMIND's `readcoupled.R` switches to `rs --found-in-slurm DIR` (above). `promptAndRun` and the disabled
  `rs2` wrapper are not ported.

### Release notes of the Python package (0.31.0)

- New: the `rs` console script (typer), a drop-in for `R/commandLineInterface.R` with `--found-in-slurm`;
  the public `Run` object (`modelstats.Run`, `RunState`, `Convergence`, `MifState`, `iter_runs`); the
  parity functions `get_run_status`, `found_in_slurm`, `loop_runs`, `get_sanity_checks`; the `modeltests`
  console script for the REMIND AMT with a JSON state machine, a lock, one log per cycle, a failure
  notification, `--dry-run` and the five commands `start`, `evaluate`, `run`, `status`, `reset`.
- Changed against the R code, by decision: D-08, D-11, D-14, D-26 for `rs` (above); D-24 for the AMT
  (implementation artefacts of `R/modeltests.R` are not reproduced, rule-level thresholds are; the list is in
  `docs/amt.md`); D-25 for `Run` (cleaner semantics than the parity record, listed in `docs/run-object.md`);
  D-15, the Mattermost payload built with `json.dumps`.
- Not ported: `promptAndRun` and `rs2` (disabled on the cluster), the MAgPIE branch of `modeltests`
  (`model = "MAgPIE"`, the `magpie4::addToDataChangelog` bridge), `lucode2::sendmail`, the usage log the `rs`
  wrapper writes (it stays in the wrapper).
- Kept: every suspected bug of the R code that a golden pins (the bug register of the migration record,
  BUG-001 to BUG-082, each with its status), among them the `> 10` calibration-file threshold of `Clb_converged`
  (BUG-001) and the `Abort ... *Infes` equality test (BUG-002), which the AMT verdicts depend on; fixing any
  of them is a separate decision with the model owners.
- Tooling: `pyproject.toml` (hatchling, src layout, `requires-python >= 3.14`, LGPL-3.0-only), `uv.lock`,
  ruff, `mypy --strict`, pytest tiers (`golden` and `sandbox` markers, deselected by default), pre-commit
  hooks and the GitHub Actions workflow `python.yml` (checks on 3.14 and the wheel job).

### The migration record

The port was specified, tested and reviewed against a record that is kept outside the repository: the
migration plan with its behavioural contract and the decision table of allowed differences (the `D-`
numbers above), the bug register of the R code (the `BUG-` numbers), the R goldens of every family
(`status`, `runtype`, `slurm`, `sort`, `printoutput`, `looprun`, `sanity`, `rs`, `amt`) with the case lists
they were made from, the fixture snapshot of PIK-internal runs they were read from, and the sandbox harness
that generated them. Docstrings cite its documents by number (`02` 4.3 is section 4.3 of the library notes,
`03` 3.5 the decision table, `06` the user amendments the rewrite follows). The directory `migration/` is
gitignored; the golden and sandbox tiers (`-m golden`, `-m sandbox`) skip as a whole when it is absent and
run on a checkout that has it. The pull request that introduced the package summarises the decisions and
the register.

## Installation

For installation of the most recent package version an additional repository has to be added in R:

```r
options(repos = c(CRAN = "@CRAN@", pik = "https://rse.pik-potsdam.de/r/packages"))
```
The additional repository can be made available permanently by adding the line above to a file called `.Rprofile` stored in the home folder of your system (`Sys.glob("~")` in R returns the home directory).

After that the most recent version of the package can be installed using `install.packages`:

```r
install.packages("modelstats")
```

Package updates can be installed using `update.packages` (make sure that the additional repository has been added before running that command):

```r
update.packages()
```
