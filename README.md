## Purpose and Functionality

A collection of tools to analyze model runs.

## Python package

The Python port of **modelstats** (same version, `pyproject.toml`) ships the `rs` command, the `Run`
object and the `modeltests` command. It is being developed on this branch phase by phase
(`migration/06-user-requests.md` section 7); the R package described further below stays available during
the transition.

### Installation with uv

Python 3.14 or newer and [uv](https://docs.astral.sh/uv/):

```sh
uv tool install modelstats                                 # the commands rs and modeltests, from a release
uv tool install ./dist/modelstats-0.31.0-py3-none-any.whl  # from a wheel built with `uv build`
uv tool upgrade modelstats
```

From a checkout, `uv sync --locked` creates `.venv` with the locked dependency set, `uv run rs` runs the
command from it and `uv build` builds the wheel and the sdist (`uv run pytest -m golden tests/packaging`
installs the wheel into a fresh environment and with `uv tool install` and checks the installed `rs`;
`migration/harness/checks/cli_install_check.sh` does the same from the shell). On the cluster a shared
environment is planned so that nobody installs anything (`migration/03-migration-plan.md` phase 7).

### The `rs` command is a drop-in

`rs` is the command line of `R/commandLineInterface.R` with the same options (`-A -b -C -d N -f REGEX
-l -m -p -s -t -u USER`), bundled short flags (`rs -mltpbf PkBudg`), the same path argument (a
comma-separated list of run folders, main folders or output folders, `.` by default) and the same output
byte for byte: the tables on stdout, the messages on stderr, the same exit status. Parity is verified against
goldens generated by the R package in a sandbox (`migration/goldens/rs`, `migration/harness/README.md`).
The differences are the approved decisions of `migration/03-migration-plan.md` section 3.5: the layout of
`rs --help` (D-11), the natural sort of the folder names without the ICU collation (D-14), the random
`Did you know?` hint (D-08), and `rs -A` reading the AMT state file `amt-state.json` before `runcode.rds`
(D-26).

```sh
rs                        # the run in the working directory, or every run below it
rs -A -f SSP2-NPi         # the recent automated model tests matching a pattern
rs -C -u alf -d 5         # the current runs of user alf, the last 5 days included
rs -s path/to/output      # the sanity-check overview
```

### The `Run` object

```python
from modelstats import Run, RunState

run = Run("/p/projects/remind/modeltests/remind/output/SSP2-NPi-AMT_2026-09-28_10.30.27")
print(run.status, run.convergence, run.iterations.current, run.warnings, run.runtime)
if run.status is RunState.COMPLETED and run.convergence.is_converged:
    print(run.summation_errors, run.mif, run.to_status_record())
```

`Run` reads a run folder the way `rs` does, lazily and at most once per file, and presents the result with
Python types (enums for the status, the convergence and the mif state, numbers and `timedelta`, `None` for
a missing value); `run.to_status_record()` is the R-compatible record `rs` prints. The full API, the
`RunState` table and the differences from the R view are in [docs/run-object.md](docs/run-object.md).

### The `modeltests` command

`modeltests` replaces the `Rscript -e 'modelstats::modeltests(...)'` line of the REMIND automated model tests
(AMT) cron job (`migration/06-user-requests.md` sections 3 and 4): `modeltests run` starts a cycle when none is
running and evaluates it otherwise (the drop-in for the old `.testsstatus` toggle); `start`, `evaluate`,
`status` and `reset` are the single steps. The global options go in front of the command: `--dir` (the REMIND
checkout), `--report-repo` (the clone that receives README.md), `--user`, `--mattermost-url-env` (default
`AMT_MATTERMOST_URL`; unset means no notification), `--publish/--no-publish`,
`--compare-scenarios/--no-compare-scenarios`, `--log-dir`, `--dry-run`, `--force` and `--no-wait`. One JSON
state file (`<dir>/amt-state.json`), one lock (`<dir>/amt-state.lock`) and one log per cycle
(`<log-dir>/amt-<cycle id>.log`) replace the `.testsstatus` toggle and the `.rds` state files; only
`runcode.rds` keeps being written, for `rs-r -A`. Exit statuses: 0 the command did what it says, 1 the cycle
crashed and the state is `failed` (a Mattermost message is sent when a URL is configured), 2 refused before any
effect. REMIND only: the MAgPIE weekly tests stay with the R package (D-27). The cron lines, the state machine,
the log, the recovery steps and what changed against the R version are in [docs/amt.md](docs/amt.md), the
operator's guide.

### The R package during the transition

The R package stays in this repository with the version the Python package mirrors
(`tests/unit/test_version.py`). On the cluster the `rs` wrapper
(`/p/projects/rd3mod/tools/rs`) switches to the Python entry point and the R command line stays available
as `rs-r`, with `RS_IMPL=r` as the escape hatch for one release (`migration/03-migration-plan.md` phase 7).
Both implementations read the AMT cycle's regular expression from the same place: the Python AMT keeps
writing `runcode.rds` next to its JSON state, so `rs -A`, `rs-r -A` and `remindstatus` agree while both
exist (`migration/06-user-requests.md` section 3.4).

### `rs --found-in-slurm DIR` for scripts

REMIND's `readcoupled.R` asks whether a coupled run is still in SLURM. The Python command answers without
loading an R package: `rs --found-in-slurm DIR` prints exactly the string `foundInSlurm(DIR)` returns
(`no`, the QOS of the run's own job with ` startup` or ` pending` appended where R appends it, another
user's name, or `<n> users`) plus one newline on stdout and nothing else: no announcements, no hint, no
table; exit status 0. On an error it prints nothing on stdout, one message on stderr and exits 1. The
contract is pinned by `tests/golden/test_rs.py::test_found_in_slurm_contract` and checked on the installed
command by `tests/packaging/test_wheel.py`.

## Installation

For installation of the most recent package version an additional repository has to be added in R:

```r
options(repos = c(CRAN = "@CRAN@", pik = "https://rse.pik-potsdam.de/r/packages"))
```
The additional repository can be made available permanently by adding the line above to a file called `.Rprofile` stored in the home folder of your system (`Sys.glob("~")` in R returns the home directory).

After that the most recent version of the package can be installed using `install.packages`:

```r
install.packages("modelstats")
```

Package updates can be installed using `update.packages` (make sure that the additional repository has been added before running that command):

```r
update.packages()
```
